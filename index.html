01 · The framework

How the 12 models are compared

Every model is scored on three pillars. Price is measured from published list prices. Performance is an indicative 1 to 5 rating built from public benchmarks and provider positioning. Usage covers what it takes to run the model in production.

Price

What does it cost to serve one request, and a month of requests?

  • Input and output priceUS dollars per 1M tokens, from public pricing as of October 2026.
  • Blended price3 input tokens for every 1 output token, the common industry convention.
  • Cost to serveMonthly cost for your volume and token sizes, computed in the Recommender and Cost lab.

Performance

How well does it do the job your workflow needs?

  • Reasoning depthMulti-step logic, analysis and expert questions (for example GPQA, HLE).
  • Agentic reliabilityTool calls, multi-step workflows and operating screens (for example OSWorld, DeepSWE).
  • Multimodal understandingImages and scanned documents; audio and video where supported.

Usage

Can you run it the way your product and client need?

  • SpeedHow quickly it responds, rated 1 to 5 against real-time, interactive and batch needs.
  • Context windowHow much text fits in one request, from 262K to about 1M tokens.
  • DeploymentHosted API only, or open weights you can run in your own cloud region.

How the recommender scores a model

Models that cannot do the job are removed first (for example, no image input for a scanning task). The rest are scored, then ranked.

Fit=Capability match×Speed fit×( quality weight × strength + cost weight × cost score )

Capability match drops sharply when a rating is below what the task needs. Cost score is relative on a log scale across the remaining models. You set the quality and cost weights with one slider.
